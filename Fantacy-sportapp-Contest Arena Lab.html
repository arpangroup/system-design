Naive mode: each simulated request reads the current filled-slot count, "thinks" for a random moment, then writes count+1 — a textbook check-then-act race. Atomic mode: each request executes a single conditional UPDATE ... WHERE filled_slots < total_slots with no gap between the check and the write.

Publishing one event computes a single point delta, looks up every drafted team via a precomputed player→team index, and increments each one's score in a sorted-set leaderboard — never a full recompute.
